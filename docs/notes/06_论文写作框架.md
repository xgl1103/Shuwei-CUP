# 数维杯 B 题论文写作框架

## 0. 写作定位

本文建议将论文主线定位为：

```text
面向多源异构文档的智能文件治理模型：
统一解析与 OCR 增强 -> 可解释主题发现 -> 新文档归类 -> 风险复核与资源约束优化
```

论文不要写成“做了一个程序”，而要写成“围绕文件治理业务建立了一套可解释、可复核、可落地的数学模型”。代码和前端界面作为模型求解、结果展示和人工复核机制的支撑材料。

## 3. 摘要框架

摘要建议分 4 段写。

第一段：问题背景与总体思路。

```text
针对多源异构文件格式复杂、历史类别未知、新文件信息不完整以及人工复核资源有限等问题，本文构建了一套“解析-主题发现-归类判别-风险复核”的智能文件治理模型。
```

第二段：问题一方法与结果。

```text
对于问题一，首先对 Word、PDF、Excel、图片等文件进行统一解析，并采用 OCR 补充文档中的图片文字信息；随后构建融合标题、正文、表格和 OCR 文本的分析文本，使用 TF-IDF 表征文档关键词分布，再通过 TruncatedSVD 降维和 MiniBatchKMeans 聚类得到历史文件的细粒度主题原型。通过 k 值消融实验，综合轮廓系数、主题碎片化和下游分类稳定性，最终选取 k=160 作为主题原型数。
```

第三段：问题二方法与结果。

```text
对于问题二，本文以问题一得到的主题原型和主题词典为基础，构造基于语义相似度、关键词覆盖率和字段完整度的文档归类模型。对数据集 2 的半结构化记录和数据集 3 的匿名记录分别进行归类，并设置最高相似度阈值与类别间隔阈值，将边界样本划分为多类待判别或无法归类，从而避免低置信度样本被强制分配。
```

第四段：问题三方法、结果和创新。

```text
对于问题三，进一步将问题二输出的置信度、分类边界状态和文本敏感信号转化为错分风险、复核必要性和紧急程度三类指标，采用 AHP 确定综合权重，并在数据集 4 的资源约束下建立人工复核分配模型。结果表明，该方法能够在保持自动归档效率的同时，将高风险、低置信度和高敏感度文件优先纳入人工复核队列。本文的创新点在于将无监督主题发现、可解释归类和资源受限复核统一到同一条文件治理链路中。
```

关键词：

```text
多源异构文件；主题发现；TF-IDF；MiniBatchKMeans；人工复核；AHP
```

## 6. 模型假设

建议列 6-8 条，不要太空。

```text
假设1：题目提供的文件数据能够代表待治理文件的主要主题类型，历史数据中的主题结构可迁移到新文件。
假设2：文档标题、正文、表格字段和 OCR 文本均包含有效主题信息，但不同字段的可信度和信息量不同。
假设3：同一主题下的文档在关键词分布和低维语义空间中具有相似性，因此可用向量距离和相似度刻画主题接近程度。
假设4：对于类别边界模糊的文件，不强制唯一归类，而是进入多类待判别或人工复核队列。
假设5：文件中的金额、审批、合同、药品、专利、截止时间等信号能够反映人工复核必要性和紧急程度。
假设6：数据集4给出的资源约束在计算周期内固定不变，人工复核耗时可由文本长度、风险等级和文件复杂度近似估计。
假设7：OCR 存在识别误差，但其补充信息总体有助于降低图片型文档的信息缺失。
```

## 7.1 算法流程与公式总览

正式论文中可在符号说明后增加一个“算法流程总览”小节，用于把全文算法统一起来，避免读者认为三问是割裂的。

整体流程可写成：

```text
多源文件
→ 统一解析与 OCR 增强
→ 文本降噪与特征构建
→ 问题一：历史文件主题原型发现
→ 主题族归并与业务命名
→ 问题二：新文件归类与边界判别
→ 问题三：复核优先级评分
→ 资源约束下的人工复核分配
→ 人工核查反馈
```

主要算法及作用：

| 阶段 | 算法或方法 | 作用 |
|---|---|---|
| 文件解析 | 多格式解析 + OCR | 处理 Word、PDF、Excel、图片等异构文件 |
| 文本降噪 | 规则清洗、重复行过滤、网页噪声剔除 | 降低导航栏、版权、URL、乱码等噪声干扰 |
| 文本表示 | TF-IDF | 构建可解释关键词权重向量 |
| 降维 | TruncatedSVD / LSA | 降低高维稀疏文本向量噪声 |
| 主题发现 | MiniBatchKMeans | 从 dataset1 中发现细粒度主题原型 |
| 参数选择 | 轮廓系数 + 小簇数量 + 下游分类压力 | 选择 `k=160` |
| 主题收口 | 主题族归并规则 | 将细粒度原型映射为业务大类 |
| 新文件归类 | 余弦相似度 + 关键词重合 + 字段加权 | 将 dataset2/dataset3 映射到主题体系 |
| 边界判别 | 阈值与间隔判别 | 输出 `assigned` / `multi_class` / `unclassifiable` |
| 复核评分 | 错分风险、复核必要性、紧急程度 | 构建问题三评价指标 |
| 权重确定 | AHP 层次分析法 | 得到综合复核优先级权重 |
| 资源分配 | 资源约束贪心分配 | 在工时和数量约束下选择复核对象 |
| 模型检验 | 分层抽样人工核查 | 检验边界样本分类合理性 |

核心公式汇总：

| 模块 | 公式 | 说明 |
|---|---|---|
| TF-IDF | \(\operatorname{tfidf}(t,d)=\operatorname{tf}(t,d)\log\frac{N}{1+n_t}\) | 突出主题区分词 |
| SVD | \(X \approx U_r\Sigma_rV_r^T\) | 将高维稀疏文本矩阵压缩到低维语义空间 |
| KMeans | \(\min \sum_{k=1}^{K}\sum_{z_i\in C_k}\|z_i-\mu_k\|^2\) | 学习历史文件主题原型 |
| 余弦相似度 | \(\cos(z_i,\mu_k)=\frac{z_i\cdot\mu_k}{\|z_i\|\|\mu_k\|}\) | 衡量文档与主题原型接近程度 |
| 字段加权相似度 | \(s_{ik}= (0.75+0.25m_i)\sum_{f\in F_i}\omega_f[\cos(z_{if},\mu_k)+\gamma q_{ifk}]\) | 融合标题、正文、表格、OCR 和关键词证据 |
| TopK 置信度 | \(p_i=\frac{\exp(s_{i1})}{\sum_{j\in \operatorname{TopK}(i)}\exp(s_{ij})}\) | 衡量最高候选在 TopK 内的相对优势 |
| 边界间隔 | \(\Delta_i=s_{i1}-s_{i2}\) | 判断是否为多类边界样本 |
| AHP 优先级 | \(P_i=w_RR_i+w_NN_i+w_UU_i\) | 汇总错分风险、复核必要性和紧急程度 |
| 资源优化 | \(\max\sum_iP_ix_i\)，\(\sum_ih_ix_i\le H_s\)，\(\sum_ix_i\le L_s\) | 在资源约束下选择复核文件 |

这一节的写作目标是证明：本文不是简单堆叠算法，而是把文本表示、无监督主题发现、可解释分类、风险排序和资源分配组织成一条可落地的治理链路。

## 9. 问题一：历史文件主题体系构建

### 9.1 建模目标

```text
问题一的目标是在缺乏人工类别标签的情况下，从数据集1中发现稳定、可解释、可迁移的主题结构，并形成后续分类使用的主题原型和主题词典。
```

### 9.2 文本向量化模型

使用 TF-IDF：

\[
\operatorname{tfidf}(t,d)=\operatorname{tf}(t,d)\log\frac{N}{1+n_t}
\]

其中 \(t\) 为词项，\(d\) 为文档，\(N\) 为文档总数，\(n_t\) 为包含词项 \(t\) 的文档数。

论文解释：

```text
TF-IDF 能够降低高频通用词的权重，突出对主题区分更有价值的关键词，适合用于可解释主题发现。
```

### 9.3 SVD 降维

```text
由于 TF-IDF 向量维度较高且较稀疏，本文采用 TruncatedSVD 将文档向量压缩到低维语义空间，以减少噪声并提升聚类稳定性。
```

### 9.4 MiniBatchKMeans 主题发现

目标函数：

\[
\min \sum_{k=1}^{K}\sum_{z_i \in C_k}\|z_i-\mu_k\|^2
\]

说明：

```text
MiniBatchKMeans 每次使用小批量样本更新聚类中心，适合较大规模文档集合。聚类后，每个簇的中心表示一个主题原型，簇内 TF-IDF 权重最高的词构成主题关键词。
```

### 9.5 k 值选择实验

必须把我们的消融实验写进去，这是论文最有说服力的部分。

下表是选择 `k` 时的基础边界策略对照，后续问题二边界优化是在确定 `k=160` 后单独进行的。

| k | 轮廓系数 | refined topics | assigned | multi_class | unclassifiable | 小于等于10条小簇 |
|---:|---:|---:|---:|---:|---:|---:|
| 90 | 0.2733 | 90 | 1601 | 2841 | 77 | 11 |
| 120 | 0.2492 | 120 | 1135 | 3309 | 75 | 25 |
| 160 | 0.2916 | 160 | 1275 | 3178 | 66 | 59 |
| 200 | 0.2733 | 200 | 702 | 3752 | 65 | 85 |
| 240 | 0.3015 | 239 | 837 | 3614 | 68 | 129 |
| 288 | 0.3242 | 287 | 578 | 3880 | 61 | 180 |

论文结论：

```text
k=288 的轮廓系数最高，但小簇数量过多，导致主题体系碎片化，并显著增加下游多类待判别样本。k=90 较稳定，但主题过粗。综合轮廓系数、主题粒度、下游分类可判别性和人工复核成本，本文选择 k=160 作为主题原型数。
```

### 9.6 主题族归并

对应代码：

```text
scripts/05_refine_topic_families.py
src/bdoc/topic_families.py
src/bdoc/topic_splitting.py
```

写作重点：

```text
聚类得到的是细粒度主题原型，不直接等同于最终业务分类。本文进一步依据主题关键词、代表文档标题和内容领域规则，将细粒度主题映射到内容主题族，如教育科研与学术文献类、财政金融与宏观经济类、医药卫生与药品类、企业投资与房地产类等。
```

因此，问题一输出可以理解为“原型层”，而不是直接面向用户使用的最终目录树；后续问题二会在该原型层基础上生成更适合文件治理场景展示和复核的业务分类层。

注意：这里要强调“内容分类”，避免评委觉得只是题材格式分类。

## 10. 问题二：新文件归类与评价指标

### 10.1 建模目标

```text
问题二的目标是将问题一得到的历史主题体系迁移到数据集2和数据集3，对新文件进行可解释归类，并识别边界样本。
```

### 10.2 问题一主题原型与问题二业务分类的关系

需要说明的是，问题一得到的 160 个主题并不直接作为最终业务类别名称使用，而是作为细粒度主题原型库。问题二在分类时，首先将数据集2和数据集3的新文件映射到问题一得到的主题原型编号 `topic_cluster_id`，再根据主题关键词、代表文档、主题族规则和领域词证据，将细粒度原型归并为业务可解释的大类，并进一步细分为具体子类。

因此，问题二中的“教育科研与学术文献类”“政府治理与公共管理类”等类别名称，并不是脱离问题一重新构造的分类体系，而是对问题一主题原型的层级化表达。问题一提供可迁移的主题原型，问题二完成从主题原型到业务目录的应用层映射，问题三再利用问题二输出的置信度、边界状态和风险信号进行人工复核优先级排序。

层级关系可写成：

```text
问题一：160 个细粒度主题原型
        ↓

        ↓
```

### 10.3 主题原型分类模型

对应代码：

```text
scripts/04_classify_documents.py
src/bdoc/classification.py
```

相似度：

\[
s_{ik}= \left(0.75+0.25m_i\right)\sum_{f\in F_i}\omega_f
\left[\cos(z_{if},\mu_k)+\gamma q_{ifk}\right]
\]

其中：

- \(F_i\)：文档 \(d_i\) 中可用的字段集合，包括标题、正文、表格文本和 OCR 文本等；
- \(\omega_f\)：字段 \(f\) 的信息权重；
- \(z_{if}\)：文档 \(d_i\) 在字段 \(f\) 上的低维文本向量；
- \(\mu_k\)：第 \(k\) 个主题原型中心；
- \(q_{ifk}\)：字段文本与第 \(k\) 个主题词典的关键词重合得分；
- \(\gamma\)：关键词证据的融合权重；
- \(m_i\)：字段覆盖率，用于惩罚可用字段过少导致的信息不足。

该式对应实际实现中的“字段加权相似度 + 关键词证据 + 字段覆盖修正”。因此，模型不是只根据整篇文本一次性计算相似度，而是先在不同字段上分别打分，再按字段信息量融合。

### 10.4 字段加权融合

论文应解释 dataset2 信息不完整：

```text
对于字段残缺的半结构化记录，本文不简单丢弃缺失字段，而是对标题、正文片段、表格文本和 OCR 文本分别计算主题相似度，再按字段信息量加权融合。缺失字段不参与加权，从而降低字段缺失对分类结果的影响。
```

### 10.5 置信度与边界判别

置信度：

\[
p_i=\frac{\exp(s_{i1})}{\sum_{j\in \operatorname{TopK}(i)}\exp(s_{ij})}
\]

其中 \(s_{i1}\) 表示最高候选主题得分，\(\operatorname{TopK}(i)\) 表示文档 \(d_i\) 的前 \(K'\) 个候选主题集合。当前实现中取前三个候选主题计算相对置信度，避免低排名主题对边界判断产生过多干扰。

边界间隔：

\[
\Delta_i=s_{i1}-s_{i2}
\]

判别规则：

```text
若最高得分低于阈值，则标记为无法归类；
若最高得分与次高得分差距过小，且无法通过主题家族或规则证据消歧，则标记为多类待判别；
若竞争主题属于同一原型家族，或规则证据足以支持最高候选，则输出唯一归类并保留复核原因；
否则输出唯一归类结果。
```

这部分是论文亮点：不是硬分，而是保守分类。

## 11. 问题三：人工复核优先级与资源约束优化

### 11.1 建模目标


### 11.2 三个一级指标

对应代码：

```text
scripts/06_review_prioritization.py
src/bdoc/review_prioritization.py
```

三个指标：

1. 错分风险 \(R_i\)：由分类状态、置信度、边界间隔、字段完整度、解析状态决定。
2. 复核必要性 \(N_i\)：由金额、审批、合同、采购、药品、专利等敏感信号决定。
3. 紧急程度 \(U_i\)：由紧急词、截止时间、限期表达等决定。

### 11.3 AHP 权重

构造判断矩阵：

\[
A=
\begin{bmatrix}
1 & a_{12} & a_{13}\\
1/a_{12} & 1 & a_{23}\\
1/a_{13} & 1/a_{23} & 1
\end{bmatrix}
\]

计算最大特征值对应的归一化特征向量作为权重，并进行一致性检验：

\[
CR=\frac{CI}{RI}, \quad CI=\frac{\lambda_{\max}-n}{n-1}
\]

当 \(CR<0.1\) 时，认为判断矩阵一致性可接受。

当前 AHP 计算结果：

| 指标 | 权重 |
|---|---:|
| 错分风险 \(R_i\) | 0.5396 |
| 复核必要性 \(N_i\) | 0.2970 |
| 紧急程度 \(U_i\) | 0.1634 |

一致性检验结果：

| 指标 | 数值 |
|---|---:|
| \(\lambda_{\max}\) | 3.0092 |
| \(CI\) | 0.0046 |
| \(CR\) | 0.0079 |

综合得分：

\[
P_i=w_RR_i+w_NN_i+w_UU_i
\]

### 11.4 优先级划分

```text

若 P_i 位于中间区间，则划为 medium，有资源时复核；
若 P_i 较低，则划为 low，可自动归档或延后处理。
```

### 11.5 数据集4资源约束优化

设：

- \(h_i\)：文件 \(i\) 的预计复核耗时；
- \(H_s\)：场景 \(s\) 可用人工小时；
- \(L_s\)：场景 \(s\) 可复核文件数量上限；

\[

\[

\[

\]

```text
本文将问题二输出的置信度、边界间隔、字段完整度、解析状态和敏感词信号转化为错分风险、复核必要性和紧急程度，使问题三的资源分配直接继承问题二的不确定性信息，而不是另起一个孤立排序模型。
```

5. **人机协同核查与误差反馈。**

```text
本文进一步设计人工复核工作台，并基于分层抽样日志对边界样本进行人工核查。人工反馈不替代自动模型，而是用于检验模型边界样本的合理性，并为后续主题词典和分类规则迭代提供依据。
```

摘要或结论中可用一句话概括：

```text
本文构建了一种面向多源异构文件的“主题原型发现—层级归类判别—风险复核优化”一体化模型，在无人工标签条件下实现历史主题体系构建、新文件可解释归类和有限资源下的人工复核优先级分配。
```

## 13.2 竞赛表达重点与风险控制

从竞赛论文角度看，当前方案的优势不在于单个算法特别复杂，而在于三问之间闭环完整、结果可解释、风险可复核、流程可落地。正式论文中应突出以下竞争点：

| 竞争点 | 论文写法 |
|---|---|
| 三问闭环 | 问题一提供主题原型，问题二完成层级归类，问题三利用不确定性安排复核 |
| 可解释性 | 输出关键词证据、候选类别、置信度、边界间隔和风险原因 |
| 稳健性 | 不强制所有文件唯一归类，保留 `multi_class` 和 `unclassifiable` |
| 参数论证 | 通过 k 值消融说明选择 `k=160` 的原因 |
| 落地性 | 数据集4资源约束和人工核查平台使模型可执行 |
| 验证性 | 通过 61 条人工核查样本进行边界样本误差分析 |

同时要避免以下风险表述：

| 风险点 | 避免写法 | 推荐写法 |
|---|---|---|
| 轮廓系数不高 | “聚类效果非常好” | “在主题粒度和下游复核成本之间取得平衡” |
| `multi_class` 较多 | “模型分类失败” | “保守边界策略，避免低置信度强制归类” |
| 教育科研类数量大 | “类别泛化严重” | “大类下仍有教务培养、院校概况、科研项目等子类结构” |
| 人工核查样本有限 | “准确率为 24/45” | “边界样本抽样核查显示模型具备可用分类基础” |
| 使用常规算法 | “算法全新” | “围绕文件治理任务完成算法组合与闭环建模创新” |

## 14. 模型不足与改进

建议诚实但不削弱：

```text
本文模型主要基于 TF-IDF 和线性降维表示，对深层语义关系的捕捉有限；OCR 结果可能受到图片质量影响；主题族归并规则仍需要结合少量人工审阅进行校准。后续可引入中文预训练语言模型生成语义嵌入，或在人机协同复核过程中积累人工修正标签，进一步训练有监督分类器。
```

可以提 RAG/Agent 但不要作为已实现主模型：

```text
在实际系统推广中，可进一步引入 RAG 检索增强机制，为人工复核人员提供相似历史文件、主题词典和分类依据；也可构建 Agent 式复核助手，自动生成分类解释和风险摘要。
```

## 22. 正式写作执行约束

### 22.1 官方 Word 模板硬性要求

已从赛题文件夹中的 `2026年第十一届数维杯大学生数学建模挑战赛（春季赛）论文Word模板及格式规范.doc` 提取格式要求，正式写作和排版时按以下规则执行：

- 论文第一页为摘要专用页，包含题目、摘要和关键词，不需要英文摘要。
- 中文摘要 300-600 字，必须控制在一页内，摘要只接受文字描述，不放图表。
- 题目用三号黑体；“摘要”用三号黑体加粗；摘要正文宋体小四。
- 关键词 3-5 个，用分号分隔，最后一个关键词后不加标点。
- 正文页码从 1 开始连续编号，页码位于页脚中部。
- 正文不超过 30 页。
- 正文每页页眉需显示队伍号和页码，例如 `Team # SHUWEI2600001 Page 1 of 9`；正式提交前必须替换模板队伍号。
- 正文宋体小四，行间距 1.5 倍。
- 图题五号宋体，居中放在图下方，按章编号，如图 5-2。
- 表题五号宋体，居中放在表上方，按章编号，如表 5-4。
- 参考文献至少 5 篇，正文引用处用方括号编号，参考文献需重新起页。
- 附录需重新起页，至少包含核心源程序、软件环境、运行命令和主要输出说明。
- 最终提交论文必须为 PDF 文档，承诺书为单独文档，不放入论文正文。

### 22.2 图片占位策略

当前论文图片已有初步版本，但后续仍会继续优化。因此正文写作时不强依赖最终图片样式，而采用“图位先行、图片后替换”的策略：


数据型图表必须来自真实结果文件；流程型、概念型图可先用文字描述和占位符承接，后续替换为最终美化图片。

### 22.3 写作执行顺序

正式写作按以下顺序推进：

1. 先写方法和结果主体：数据预处理、问题一、问题二、问题三。
2. 再写模型检验、敏感性分析、模型评价与推广。
3. 最后写摘要、问题重述、问题分析和参考文献。

这样可以保证摘要、问题分析和创新点都依赖最终稳定结果，避免前后数值或叙事不一致。
