# B题总体建模方法总纲

## 1. 目标

本项目面向 B 题“多源异构文件识别、归类与治理优化”建立统一的方法框架。  
核心目标有三层：

1. 把来自不同格式、不同清晰度、不同结构层次的文件统一成可计算的文本表示。
2. 在历史文件上建立稳定、可解释的主题原型库。
3. 将后续流入的新文件归入既有主题体系，并输出置信度、风险分级和人工复核建议。

## 2. 问题理解

题目不是单纯分类，也不是单纯 NLP，更像一个“文件治理系统”。

它可以拆成三步：

1. 统一解析
2. 主题发现与归类
3. 风险分级与人工复核

因此，整体方案不能只依赖一个黑盒模型，而要同时兼顾：

- 可解释性
- 可复现性
- 跨格式适应性
- 资源约束下的可落地性

## 3. 总体思路

采用“统一解析 + 多视角特征 + 主题原型 + 检索式归类 + 置信度输出 + 人工复核”的混合框架。

一句话概括：

`解析 -> 表示 -> 原型 -> 相似度归类 -> 置信度 -> 复核`

这套方法的特点是：

- 不依赖大规模人工标签
- 对边界模糊文件更稳
- 便于解释每个结论的证据来源
- 便于后续接前端做人工复核

## 4. 数据角色划分

### 4.1 数据集1

历史真实文件数据。用于：

- 发现主题结构
- 构建主题原型库
- 形成稳定类别命名

### 4.2 数据集2

后续流入的半结构化记录数据。用于：

- 测试已建主题体系下的归类能力
- 检验跨格式迁移效果

### 4.3 数据集3

后续流入的匿名原始文件数据。用于：

- 测试面对原始异构文件时的适应能力
- 检验 OCR、结构提取和文本归类的鲁棒性

### 4.4 数据集4

业务规则与资源约束表。用于：

- 定义风险阈值
- 约束人工复核顺序
- 指导资源分配优化

## 5. 第一层：统一解析

这一层负责把所有文件变成统一结构。

统一输出应至少包含：

- `doc_id`
- `dataset`
- `file_path`
- `file_name`
- `suffix`
- `title`
- `time_info`
- `raw_text`
- `clean_text`
- `table_text`
- `ocr_text`
- `parse_status`
- `parse_notes`
- `char_count`

### 5.1 解析原则

1. 尽量保留原始证据，不做过度清洗。
2. 对图片、扫描件、嵌图文档进行 OCR 补全。
3. 对 docx / xlsx 这类结构化容器，尽量提取正文、表格、批注、隐藏内容等补充信息。
4. 输出统一 JSONL 和索引 CSV，便于后续复用。

### 5.2 当前已实现

解析脚本 `01_parse_documents.py` 已支持：

- `txt`
- `docx`
- `pdf`
- `xlsx`
- `jpg/png`

并带有：

- OCR 缓存
- 扫描版 PDF OCR
- Word 嵌图 OCR
- Excel 隐藏表与批注提取
- 安全写回机制

## 6. 第二层：主题发现

### 6.1 目标

在数据集1上建立主题原型库，让历史文件形成若干稳定主题簇。

### 6.2 方法

当前采用：

1. 分词与停用词过滤
2. TF-IDF 向量化
3. TruncatedSVD 降维
4. MiniBatchKMeans 聚类
5. 轮廓系数与下游分类效果共同选择簇数

当前主方案采用 `k=160`。该值不是单纯追求轮廓系数最高，而是在 `k=90/120/160/200/240/288` 消融实验后，综合主题纯度、碎片化程度、下游 `multi_class` 比例和人工复核成本确定的折中方案。

### 6.3 输出

主题发现输出五类结果：

- `topic_assignments.csv`
- `topic_summary.csv`
- `topic_summary_refined.csv`
- `topic_family_map.csv`
- `topic_meta.json`

其中 `topic_summary.csv` 给出：

- 主题编号
- 主题名称
- 主题规模
- 主题关键词
- 代表文档

### 6.4 题一的作用

题一不是最终定题，而是给题二提供“主题原型库”。

也就是说，题一负责回答：

> 历史文件大致能分成哪些语义簇？

## 7. 第三层：新文件归类

### 7.1 目标

把数据集2和3的新文件映射到题一建立的主题原型中，并输出置信度与复核建议。

### 7.2 方法

当前采用“检索式归类 + 规则校验 + 置信度输出”：

1. 先把新文件转成和历史文件一致的表示。
2. 在主题原型库中检索最相近主题。
3. 结合关键词重叠、相似度边距、文本长度和解析状态做校验。
4. 对同一主题原型家族内的细碎竞争进行消歧，对证据充分的轻微跨类竞争采用规则辅助判定。
5. 输出主类、候选类、置信度和人工复核标记。

### 7.3 为什么不直接用黑盒分类器

因为当前数据存在：

- 格式差异大
- 文本长短不一
- 部分文件只有图片或扫描件
- 新旧数据分布不完全一致

所以更稳妥的方式是：

`主题原型 + 相似度归类 + 规则修正`

### 7.4 题二输出

题二当前输出：

- `classification_results.csv`
- `classification_summary.csv`
- `review_queue.csv`
- `classification_meta.json`

其中 `review_queue.csv` 是后面前端复核界面的核心数据源。

## 8. 第四层：风险分级与人工复核

### 8.1 目标

在题二归类结果基础上，结合文本长度、置信度、相似度边距、解析状态等因素，形成复核优先级。

### 8.2 建议指标

每个文件建议至少考虑：

- `confidence_score`
- `score_margin`
- `parse_status`
- `char_count`
- `review_reason`
- `evidence_terms`

### 8.3 复核逻辑

- 高风险：优先人工复核
- 中风险：进入复核队列
- 低风险：自动通过或批量处理

### 8.4 题三和前端

题三最适合做成“复核工作台”：

- 待复核列表
- 文件详情页
- 候选主题对比
- 证据片段展示
- 人工确认 / 改类 / 驳回
- 操作日志留痕

## 11. 论文表述原则

论文里要强调：

- OCR、embedding、相似度检索只是实现手段，不是结论本身。
- 结论应该落在“统一解析、主题发现、迁移归类、风险复核、资源约束优化”这条主线上。
- 整个方法要能回到原始证据，不能只报一个分类结果。

## 13. 增强版补充思路

这一节吸收外部方案中比较有价值的部分，但保持和当前代码体系一致。

### 13.1 问题一的补充理解

问题一的核心不建议写成纯 `LDA` 主导，更稳的写法是：

- 解析层统一抽取正文、表格、OCR、批注、标题等信息
- 表示层用 `TF-IDF + SVD + 聚类` 建主题原型
- 主题名称由高频词和代表文档共同决定

`LDA` 可以作为对照实验或补充解释，但不建议作为当前主线。

### 13.2 问题二的增强写法

可以把博主思路里的“主题词典”保留下来，但改成更贴近当前实现的表述：

- 每个主题原型都维护一个主题词典
- 对新文件按字段分别打分
- 字段缺失时降权，而不是直接丢弃
- 设两个阈值：
  - `max_score < δ`：无法归类
  - `top1 - top2 < ε`：多类归属 / 待复核

这样既保留了“词典 + 相似度”的解释性，也和当前 `review_queue.csv` 的输出一致。

### 13.3 问题二的评价指标

博主提到的四个维度是有价值的，可以保留为论文评价框架：

1. 准确性
   - 用 `F1` 或一致率衡量。
2. 置信度
   - 用分类最大概率或相似度归一化值衡量。
3. 可解释性
   - 用关键词覆盖率、证据片段命中率衡量。
4. 迁移适用性
   - 用新旧数据的类别分布差异或 `KL` 散度衡量。

### 13.4 问题三的增强写法

题三的打分逻辑可以保留博主的三项结构：

- 紧急程度
- 错分风险
- 复核必要性

然后用 `AHP` 定权，并做一致性检验 `CR < 0.1`。  
这部分很适合写成论文里的决策层。

### 13.5 资源约束场景

数据集4给出的资源约束，适合用贪心或背包思想处理：

- 先按综合风险分排序
- 再在工时、数量、处理能力约束下分配人工复核名额

这部分和前端复核工作台是连起来的，后面可以直接作为可视化模块的排序规则。
