## 1. 总体判断

当前论文框架的大方向是对的，能够覆盖赛题三问，并且主线比较清楚：

```text
统一解析/OCR增强
-> 问题一：历史文件主题原型发现
-> 问题二：新文件层级归类与边界判别
-> 问题三：人工复核优先级与资源约束分配
-> 人工核查平台抽样验证
```

从竞赛论文角度看，框架已经具备三个优势：

1. 三问之间不是割裂建模，而是有信息传递链条。
2. 没有把普通算法硬说成原创算法，而是强调“任务适配 + 闭环治理”。
3. 对 `multi_class`、人工核查样本有限、轮廓系数不高等风险点已经有防守性叙述。

但正式写作前还需要收紧。当前最大的风险不是模型本身，而是论文表达中可能出现“数值前后不一致”“验证强度被夸大”“公式变量未定义完整”“问题二结果与问题一关系解释不够靠前”等问题。

## 2. 必须优先修改的问题

### 2.2 摘要需要加入最终数值，不能只写方法

当前摘要框架讲清了方法，但结果数字不够集中。正式摘要必须出现三问的核心结果，否则评委无法快速判断模型是否完成任务。

建议摘要中加入：

```text
问题一中，本文在 dataset1 的 3396 条历史记录中选取 3133 条有效文本参与主题发现，覆盖率为 0.9226，最终确定 k=160 个主题原型，轮廓系数为 0.2916。

问题二中，本文对 dataset2 和 dataset3 共 4519 条新记录进行归类，其中 assigned=3159，multi_class=1294，unclassifiable=66。

问题三中，基于 AHP 得到错分风险、复核必要性和紧急程度权重分别为 0.5396、0.2970 和 0.1634，一致性比例 CR=0.0079；最终得到 high=164、medium=1932、low=2423 的复核优先级划分。
```

摘要中不要写“准确率达到多少”，因为人工核查样本是边界抽样，不是全量监督测试集。

### 2.3 k 消融实验和最终分类结果必须区分阶段

这是最容易被质疑的地方。

当前消融实验表中 `k=160` 的基础结果是：

```text
assigned=1275
multi_class=3178
unclassifiable=66
```

但最终主结果是：

```text
assigned=3159
multi_class=1294
unclassifiable=66
```

这不是矛盾，原因是两者属于两个阶段：

| 阶段 | 作用 | k=160 结果 |
|---|---|---|
| k 消融阶段 | 使用基础边界策略比较不同 k 的主题粒度影响 | assigned=1275，multi_class=3178 |
| 最终方案阶段 | 固定 k=160 后，加入主题族归并和边界优化 | assigned=3159，multi_class=1294 |

建议在 `9.5 k 值选择实验` 后补一句：

```text
需要说明的是，表中下游分类结果用于比较不同 k 在相同基础边界策略下的相对表现，并非最终提交的分类结果。本文在确定 k=160 后，进一步引入主题族归并、同族候选消歧和规则证据修正，得到最终问题二结果 assigned=3159、multi_class=1294、unclassifiable=66。
```

同时建议把消融表表头改为：

```text
基础策略 assigned
基础策略 multi_class
基础策略 unclassifiable
```

避免读者误以为它就是最终结果。

### 2.4 问题一和问题二的层级关系要放得更靠前

框架中已经有 `10.2 问题一主题原型与问题二业务分类的关系`，这是正确的。但正式论文中还应在“问题分析”章节提前讲一次，否则读者读到问题二结果时才发现类别名称不同，会产生疑问。

建议在第2章问题分析末尾加入：

```text
本文将问题一输出定义为“主题原型层”，将问题二输出定义为“业务应用层”。问题一得到的 160 个主题原型不直接作为最终目录名称，而是作为后续归类的细粒度语义基元。问题二先将新文件映射到主题原型，再根据主题关键词、代表文档和领域规则归并为业务大类，并在大类内部进一步细分子类。
```

正式论文中建议固定使用以下表达：

```text
问题一：主题原型层
问题二：业务分类层
问题三：复核决策层
```

这会让三问关系更清楚。

### 2.5 字段加权公式需要补全变量定义

框架中字段加权公式为：

```text
s_ik = (0.75 + 0.25 m_i) * sum_{f in F_i} omega_f [cos(z_if, mu_k) + gamma q_ifk]
```

这个公式方向正确，但正式论文中需要补全变量定义，否则看起来像临时拼出来的经验式。

建议补充定义：

| 符号 | 含义 |
|---|---|
| \(F_i\) | 文档 \(d_i\) 中可用字段集合，包括标题、正文、表格文本、OCR 文本 |
| \(z_{if}\) | 文档 \(d_i\) 在字段 \(f\) 上的降维向量 |
| \(\omega_f\) | 字段 \(f\) 的归一化权重 |
| \(q_{ifk}\) | 字段 \(f\) 与主题 \(C_k\) 的关键词证据得分 |
| \(\gamma\) | 关键词证据调节系数 |
| \(m_i\) | 文档字段完整度或有效信息覆盖率 |

还要补一句：

```text
当某一字段缺失时，该字段不进入求和，剩余字段权重重新归一化。
```

这样才能解释 dataset2 字段残缺和 dataset3 匿名记录的处理方式。

### 2.6 自建评价指标不要写成“新准确率”

框架中第10.7节提出了综合评价式：

```text
E_i = λ1 p_i + λ2 Q_i + λ3(1-B_i) + λ4 M_i
```

这个式子可以作为“分类质量解释指标”，但不建议在正式论文中把它写成模型主目标或准确率替代指标。原因是：

1. 赛题没有人工全量标签，不能验证它与真实准确率的单调关系。
2. 当前主输出中已经有 `confidence_score`、`score_margin`、`field_coverage`、`risk_score` 等指标。
3. 如果再造一个 \(E_i\)，评委可能会问权重 \(\lambda\) 如何确定。

建议改写为：

```text
本文不构造监督准确率，而从可分性、置信度、边界清晰度、可解释性和字段完整度五个角度评价分类结果。
```

若保留 \(E_i\)，必须说明：

```text
该指标仅用于无标签条件下的相对质量分析，不作为监督分类准确率。
```

### 2.7 问题三资源优化需要补“自动归档/延期处理”

当前第11.5节把资源优化写成：

```text
max sum_i P_i x_i
subject to sum_i h_i x_i <= H_s
           sum_i x_i <= L_s
```

这个式子只覆盖“选哪些文件人工复核”，但题目和当前结果还涉及：

```text
auto_archive
review_if_capacity
must_review
delay / postponed
```

建议把问题三结果写成三类决策：

| 决策 | 含义 |
|---|---|
| must_review | 高风险、高不确定或强敏感文件，优先人工复核 |
| review_if_capacity | 中风险文件，有资源时复核 |
| auto_archive | 低风险文件，可自动归档或延后复查 |

同时补充当前总体结果：

```text
auto_archive=2694
review_if_capacity=1227
must_review=598
```

注意这里的 `must_review=598` 是问题二/风险决策中的高风险数量，而第7章复核优先级最终 `high=164` 是资源优先级层的高优先级数量。两者不是同一个字段，正式论文中要避免混用。

### 2.8 AHP 权重顺序要统一

当前符号表写：

```text
w_R, w_N, w_U
```

而部分叙述顺序写成：

```text
错分风险、复核必要性、紧急程度
```

这是可以的，但公式、表格、正文必须统一为：

```text
P_i = w_R R_i + w_N N_i + w_U U_i
```

其中：

```text
w_R = 0.5396
w_N = 0.2970
w_U = 0.1634
```

不要一会儿写 \(w_R,w_U,w_N\)，一会儿写 \(w_R,w_N,w_U\)。

### 2.9 OCR 有效性检验不能写得过强

当前框架建议写“从解析日志看，大量图片文件、扫描型 PDF 和嵌图 docx 通过 OCR 获得补充文本”。这个方向可以，但如果没有在论文中给出具体 OCR 数量、无 OCR 对照或案例，就不能写成强实验结论。

建议改为：

```text
OCR 增强主要作为预处理能力和信息补充机制，而非独立性能提升实验。本文通过解析状态、空文本比例和典型样本说明 OCR 能够补充图片型或扫描型文本的信息，但不将 OCR 识别结果作为唯一分类依据。
```

如果要强化这一节，需要补一个小表：

| 指标 | 数值 |
|---|---:|
| 图片/OCR触发文档数 | 待统计 |
| OCR 后仍 empty 数 | 11 |
| OCR 文本参与分类字段数 | 待统计 |

否则建议少写，不要把它当成主要创新点。

### 2.10 人工核查结果要避免“准确率”表述

框架中已经提醒“不建议把 24/45 写成全体准确率”，这是正确的。但正式论文还需要进一步区分两个概念：

| 概念 | 数值 | 含义 |
|---|---:|---|
| 独立核查样本 | 61 | 两批日志按 doc_id 去重后的样本数 |
| 可评价分类样本 | 45 | 人工状态为 confirmed/changed 的样本 |
| 原类别可接受 | 24 | 人工认为模型原分类可接受 |
| 人工调整类别 | 21 | 人工认为应改到更合适类别 |
| 噪声/存疑/无法归类 | 16 | 不纳入分类正确率判断 |

建议正式表述：

```text
人工核查结果表明，模型输出具备可解释的初始归类能力，但边界样本和细分类样本仍需要人工复核修正。由于抽样对象偏向高风险和边界样本，该结果不用于估计全体样本准确率。
```

不要写：

```text
模型准确率为 24/45。
```

也不要写：

```text
人工核查证明模型分类效果很好。
```

## 5. 正式论文中最应该强调的内容

建议全文反复围绕这三句话展开：

```text
问题一不是最终目录树，而是主题原型库。
问题二不是重新造类别，而是将主题原型映射为业务分类层。
问题三不是单独排序，而是继承问题二的不确定性并在资源约束下安排人工复核。
```

对应三层模型：

| 层级 | 作用 |
|---|---|
| 主题原型层 | 从历史文件中发现可迁移主题基元 |
| 业务分类层 | 将新文件映射到可解释业务大类和子类 |
| 复核决策层 | 将分类不确定性转化为人工复核优先级 |

这是当前方案最有竞争力的叙事。

## 7. 推荐下一步

建议先不急着继续扩写正文，而是先对 `06_论文写作框架.md` 做一次结构性整理：

1. 保留最终正文结构。
2. 把本文档中的“必改项”补进原框架。
3. 再根据原框架回到 `paper/数维杯B题论文正式草稿_v1.md` 修改正式论文。
